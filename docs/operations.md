# Эксплуатация и восстановление

## Ежедневная проверка

```bash
sudo systemctl is-active awg-quick@awg0 xray
sudo awg show awg0
sudo ss -lunp
sudo ss -ltnp
ip -4 rule
ip -4 route show table all
sudo nft list ruleset
```

Смотрите возраст handshake и рост RX/TX. Не делайте вывод только по одному
показателю.

## После перезагрузки

Проверьте:

1. физическая сеть получила адрес и default route;
2. модуль `amneziawg` загружен;
3. systemd-службы включены (`enabled`) и активны;
4. nftables и policy routing восстановились;
5. UDP/TCP-порты слушаются;
6. роутер сохранил port-forward и LAN-reservation.

Старое NAT/UDP-состояние домашнего роутера иногда зависает. Если сервер видит
рукопожатие и двусторонний трафик, но конкретная внешняя сеть не подключается,
переподключите клиент. Перезагрузку роутера оставляйте последним безопасным
шагом после проверки его конфигурации.

## Обновление ядра

Перед перезагрузкой после обновления:

```bash
next_kernel='<VERSION>'
test -e "/lib/modules/$next_kernel/updates/dkms/amneziawg.ko" \
  || test -e "/lib/modules/$next_kernel/updates/dkms/amneziawg.ko.xz"
```

После загрузки нового ядра:

```bash
uname -r
modinfo amneziawg
sudo systemctl status awg-quick@awg0 --no-pager
```

## Резервные копии

Храните отдельно:

- `/etc/amnezia/amneziawg/`;
- конфиги Xray и systemd unit/drop-in;
- nftables, `ip rule`/route loader;
- SSH-конфигурацию и `authorized_keys`;
- перечень peer → устройство → адрес;
- версии пакетов и ядра.

Резерв с приватными ключами должен быть зашифрован и не должен попадать в Git.
Перед изменением создавайте датированную копию, а удаление старых резервов
выполняйте только по отдельному согласованию.

## Диагностика по уровням

1. **Физическая сеть:** адрес, gateway, DNS, ping по IP.
2. **Сокет:** сервер слушает нужный UDP/TCP-порт.
3. **Handshake:** появляется свежая сессия.
4. **Туннель:** пакеты видны на AWG/TUN-интерфейсе.
5. **Forward/NAT:** счётчики правил растут в обе стороны.
6. **DNS:** запрос и ответ проходят по нужному маршруту.
7. **Приложение:** исключения, QUIC, MTU и дополнительные процессы.

Такой порядок не позволяет маскировать проблему перезапусками всего сервера.
