# Маршрутизация

## Полный туннель

AWG-клиент отправляет `0.0.0.0/0` в туннель. На сервере обязательны:

- `net.ipv4.ip_forward=1`;
- разрешённый `forward`;
- NAT/SNAT на выходном интерфейсе;
- рабочий DNS у клиента;
- обратный маршрут к адресу клиента.

## Только выбранные сети

В `AllowedIPs` клиента перечисляются только нужные подсети:

```ini
AllowedIPs = 10.66.0.0/24, 192.168.50.0/24
```

Этот режим не является интернет-VPN: остальные адреса идут напрямую.

## Исключение приложений

На Windows и Android удобнее использовать раздельное туннелирование клиента.
Каждый сетевой процесс приложения нужно добавить отдельно: для игр это часто
сама игра, launcher и update agent. На macOS/Linux приложение обычно нельзя
исключить по имени процесса средствами простого AWG-профиля — требуется
маршрутизация по IP/подсетям или отдельный network namespace.

## HOME → VPS-OUT

Для каскада создайте отдельную таблицу маршрутизации:

```bash
sudo ip route add default dev awg-uplink table 177
sudo ip rule add fwmark 0x177 lookup 177 priority 17700
```

Пакеты помечайте nftables только после того, как проверены:

- маршрут до endpoint самого `awg-uplink` остаётся через физический WAN;
- локальные сети и адреса управления не помечаются;
- при падении uplink действует выбранная политика: fail closed или fallback.

Команды выше — пример, а не готовая конфигурация. Для постоянной работы правила
нужно идемпотентно загружать systemd-службой после появления сети и AWG.

## RU/direct и foreign/VPS

Списки IP меняются. Их нужно:

1. получать из доверенного источника;
2. валидировать до замены действующего набора;
3. обновлять атомарно;
4. хранить последнюю рабочую копию;
5. не считать маршрутизацию по IP абсолютно точной из-за CDN и общих адресов.

DNS-маршрутизация по доменам в Xray может быть удобнее, но также требует
правильного DNS внутри Xray и явного `domainStrategy`.
