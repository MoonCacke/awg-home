# Архитектура

## Один сервер

```text
клиент -- AWG или VLESS --> VPS --> интернет
```

Это самый простой вариант. VPS имеет публичный адрес, принимает клиентов и
выполняет NAT в интернет.

## HOME + VPS-OUT

```text
клиент -- AWG --> HOME -- AWG uplink --> VPS-OUT --> зарубежные ресурсы
                         \\--> домашний провайдер --> локальные ресурсы
```

В такой схеме удобно разделить роли:

- `awg-clients` принимает пользовательские устройства;
- `awg-uplink` связывает HOME с VPS-OUT;
- policy routing выбирает домашний или внешний выход;
- VPS-OUT выполняет NAT для трафика, пришедшего по uplink.

Для примеров используются подсети:

- клиенты: `10.66.0.0/24`;
- uplink HOME ↔ VPS: `10.67.0.0/30`.

Это только документационные адреса. Перед развёртыванием выберите подсети,
которые не пересекаются с LAN, Docker, виртуальными машинами и другими VPN.

## VLESS как резервный вход

VLESS REALITY можно поднять на VPS параллельно AWG. Клиент выбирает:

- AWG для максимальной скорости и обычной сети;
- VLESS REALITY для сети, где UDP ограничен или AWG не устанавливает
  рукопожатие;
- каскад VLESS → VPS → AWG uplink → HOME только если действительно нужен
  доступ к домашней сети.

Не направляйте один туннель внутрь самого себя. Адрес конечного VPN-сервера
всегда должен иметь отдельный маршрут через физический интерфейс.
